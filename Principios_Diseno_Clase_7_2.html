Principios y Heurísticas de Diseño

Domina las reglas de oro del diseño pragmático. Comprende DRY, KISS, YAGNI, Separation of Concerns, Cohesión/Acoplamiento y Programación por Interfaces.

1. Heurísticas de Diseño Pragmático

Más allá de SOLID, el diseño efectivo de software se apoya en heurísticas pragmáticas acumuladas durante décadas de experiencia en la industria. Estas reglas prácticas previenen la sobreingeniería (crear soluciones excesivamente complejas para problemas sencillos) y aseguran que la base de código sea modificable y legible.

DRY (Don't Repeat Yourself)

Toda pieza de conocimiento o lógica del negocio debe tener una representación única, no ambigua y autoritativa dentro del sistema.

KISS (Keep It Simple, Stupid)

Los sistemas funcionan mejor si se mantienen simples en lugar de complejos. La simplicidad debe ser una meta clave en el código.

YAGNI (You Aren't Gonna Need It)

No programes funcionalidades o abstracciones basándote en que "las vas a necesitar en el futuro". Agrégalas solo cuando sea necesario.

DRY (Don't Repeat Yourself)

Evitar duplicidad

Toda pieza de conocimiento o lógica del negocio debe tener una representación única, no ambigua y autoritativa dentro del sistema. Evita copiar y pegar el mismo bloque de código lógico en múltiples clases.

Consecuencias de Violación

  • Dispersión de bugs por copia y pega.
  • Esfuerzo multiplicado al cambiar una regla del negocio.

Solución / Enfoque

  • Abstraer lógica común en helpers o utilidades compartidas.
  • Reutilizar componentes modulares.

// ANTES: Duplicidad de lógica para formatear monedas
public double calcularPrecioFinal(double base) {
    double impuesto = base * 0.12;
    System.out.printf("Monto formateado: $%.2f", base + impuesto);
    return base + impuesto;
}

// REFACTORIZADO (DRY): Abstracción del formateador
public class CurrencyFormatter {
    public static String format(double val) {
        return String.format("$%.2f", val);
    }
}
// ANTES: Complejidad absurda para buscar un string dentro de una lista
public boolean buscarNombre(List<String> lista, String target) {
    return lista.stream()
        .filter(n -> n.equalsIgnoreCase(target))
        .findFirst().isPresent();
}

// REFACTORIZADO (KISS): Directo, limpio y legible
public boolean buscarNombreSimple(List<String> lista, String target) {
    return lista.contains(target);
}
// ANTES: Creación de interfaces, factorías y DTOs para un simple CRUD interno temporal
public interface IUserService { void save(); }
public class UserServiceFactory { /* Lógica genérica de creación */ }

// REFACTORIZADO (YAGNI): Clase directa. No agregues abstracción si no hay múltiples implementaciones.
public class UserService {
    public void saveUser(User u) { /* Lógica directa */ }
}
// ANTES: Depender de clase concreta (Impide mockear y cambiar por otro motor de base de datos)
public class FacturaService {
    private MySQLDatabase db = new MySQLDatabase();
    public void guardar() { db.save(); }
}

// REFACTORIZADO: Programar orientado a Interfaces
public interface Repository { void save(); }
public class FacturaServiceRefactored {
    private Repository repo;
    public FacturaServiceRefactored(Repository r) { this.repo = r; } // Inyectado
}
