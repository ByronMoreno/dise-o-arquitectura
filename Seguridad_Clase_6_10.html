Seguridad y Control de Accesos

Comprende las defensas del software moderno. Domina la diferencia entre autenticación y autorización, y analiza Spring Security, Passport.js, Keycloak, OAuth2, JWT y OpenID Connect.

1. Autenticación frente a Autorización

En seguridad de aplicaciones, la protección de recursos se divide en dos fases lógicas obligatorias y secuenciales:

Autenticación (Identidad)

¿Quién eres tú?

Es el proceso de verificar que un usuario o servicio es realmente quien dice ser (ej. credenciales, tokens, biometría).

Estándares clave: OpenID Connect (OIDC), autenticación mediante JWT, inicio de sesión vía Keycloak o estrategias locales de Passport.js.

Autorización (Permisos)

¿Qué puedes hacer tú?

Es el proceso de determinar si un usuario ya autenticado tiene los derechos o roles necesarios para acceder a un recurso específico (ej. roles de administrador, scopes de API).

Estándares clave: Scopes y Roles en el protocolo OAuth2, reglas de filtrado de Spring Security (hasRole('ADMIN')).

2. Catálogo e Interactividad de Seguridad

Haz clic en cada botón para explorar la clasificación del estándar o framework, su filosofía operativa, sus pros/contras y su flujo de ejecución:

Spring Security

Tipo: Framework | Lenguaje: Java

Framework de seguridad y control de accesos sumamente robusto para aplicaciones Java y Spring. Utiliza una cadena de filtros (Security Filter Chain) interceptores para asegurar las peticiones HTTP antes de que lleguen a los controladores.

Fortalezas (Pros)

  • Protección nativa contra ataques CSRF, Session Fixation y Clickjacking.
  • Altamente modular e inyectable mediante anotaciones (@PreAuthorize).
  • Excelente integración con OAuth2 y JWT.

Debilidades (Cons)

  • Curva de aprendizaje pronunciada debido a su gran cantidad de abstracciones.
  • Configuración verbosa y compleja en proyectos sin Spring Boot.

3. Comparativa de Código de Configuración

Compara la sintaxis real para definir filtros de rutas en Spring Security, validar cabeceras Bearer en Passport o firmar un token JWT: 

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable()) // Deshabilitar CSRF para APIs stateless
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/publico/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated()
            )
            .sessionManagement(sess -> sess.sessionCreationPolicy(SessionCreationPolicy.STATELESS));
        return http.build();
    }
}
const passport = require('passport');
const { Strategy, ExtractJwt } = require('passport-jwt');

const opciones = {
  jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
  secretOrKey: 'mi_clave_secreta_super_segura'
};

// Definición de Estrategia para validar JWT
passport.use(new Strategy(opciones, async (payload, done) => {
  try {
    const usuario = await Usuario.findById(payload.sub);
    return usuario ? done(null, usuario) : done(null, false);
  } catch (err) {
    return done(err, false);
  }
}));
const jwt = require('jsonwebtoken');

const payload = {
  sub: '1234567890',
  name: 'Juan Perez',
  admin: true
};

// Generar y Firmar un Token JWT
const token = jwt.sign(payload, 'mi_clave_secreta', { algorithm: 'HS256', expiresIn: '1h' });
console.log(token);

// Verificar el Token
const datosVerificados = jwt.verify(token, 'mi_clave_secreta');
console.log(datosVerificados.name);
