TALLER DE ANÁLISIS APE-01

Taller: Descomposición Modular y Matriz de Atributos de Calidad

En este taller práctico aplicarás los fundamentos del diseño de software (RDA1) mediante la formulación de requisitos funcionales con historias de usuario INVEST, criterios de aceptación Gherkin y la caracterización de atributos de calidad en un escenario empresarial real.

🏢 Caso Empresarial: "SaludPlus Telemedicina"

La red hospitalaria SaludPlus planea lanzar una plataforma nacional de telemedicina y gestión de historias clínicas electrónicas. La plataforma atenderá a más de 100,000 pacientes concurrentes en horas pico, integrando médicos especialistas, farmacias aliadas, pasarelas de pago y laboratorios clínicos.

Retos críticos del sistema:
1. Los historiales médicos deben cumplir con confidencialidad absoluta (cifrado AES-256 y cumplimiento HIPAA).
2. La consulta de disponibilidad médica y agendamiento no debe superar los 300 ms de latencia.
3. El sistema de videollamadas y recetas electrónicas debe mantenerse operativo el 99.95% del tiempo anual.

🧩 Actividad 1: Descomposición Modular y Alta Cohesión

Descompón el sistema "SaludPlus" en módulos independientes de alta cohesión y bajo acoplamiento:

Módulo Responsabilidad Única (Cohesión Funcional) Dependencias Clave (Acoplamiento)
Auth & Security Autenticación multifactor (MFA), roles y emisión de tokens seguros. Ninguna (Módulo base / Core).
Agendamiento de Citas Gestión de calendarios, slots de disponibilidad y reservas de pacientes. Auth & Security, Módulo de Notificaciones.
Historia Clínica Digital Registro y consulta inmutable de diagnósticos, recetas y antecedentes. Auth & Security, Storage Cifrado.
Facturación y Pagos Cálculo de tarifas, emisión de comprobantes fiscales y pasarela externa. Pasarela Bancaria Externa (Webhook / REST).

📝 Actividad 2: Formulación de Historias de Usuario con BDD Gherkin

A continuación se presenta el modelo estándar a replicar para las Historias de Usuario del proyecto integrador:

HU-01: Agendamiento de Cita Virtual con Validación de Disponibilidad
Historia de Usuario:
Como: Paciente registrado en SaludPlus
Quiero: Consultar la disponibilidad de un médico especialista y reservar un turno virtual
Para: Recibir atención médica oportuna desde mi hogar

Criterio de Aceptación 1 (Flujo Exitoso):
Scenario: Reserva exitosa de turno disponible
  Given el paciente "María Gómez" ha iniciado sesión en la plataforma
  And el cardiólogo "Dr. Pérez" tiene el turno del "25/11/2026 10:00 AM" en estado DISPONIBLE
  When la paciente selecciona el turno y confirma el método de pago registrado
  Then el sistema debe cambiar el estado del turno a RESERVADO
  And debe enviar un correo de confirmación con el enlace de videoconsulta cifrado
  And la transacción debe confirmarse en pantalla en menos de 400 ms

Criterio de Aceptación 2 (Concurrencia / Conflicto):
Scenario: Intento de reserva simultánea del mismo turno
  Given dos pacientes intentan reservar el turno del "25/11/2026 10:00 AM" simultáneamente
  When el primer paciente completa la confirmación
  Then el segundo paciente debe recibir un mensaje de alerta: "El turno acaba de ser ocupado"
  And el sistema debe sugerirle los 3 turnos disponibles más próximos del mismo especialista

🎯 Actividad 3: Escenarios de Atributos de Calidad (SEI Format)

Estructura formal de 6 partes para especificar atributos de calidad de forma verificable:

Elemento del Escenario Escenario de Rendimiento (Latencia) Escenario de Seguridad (Confidencialidad)
Fuente (Source) Pacientes concurrentes desde la app móvil. Actor externo no autorizado o atacante.
Estímulo (Stimulus) 10,000 solicitudes de búsqueda de especialistas simultáneas. Intento de inyección SQL o acceso a historia médica ajena.
Artefacto (Artifact) Servicio de Búsqueda y Catálogo de Médicos. API Gateway y Servicio de Historial Clínico.
Entorno (Environment) Operación normal en hora pico de lunes por la mañana. Operación normal bajo tráfico HTTPS.
Respuesta (Response) El sistema atiende las búsquedas sin encolamiento excesivo. El sistema bloquea la petición, registra la IP en auditoría y no expone datos.
Medida de Respuesta Tiempo de respuesta p95 < 350 ms; 0 errores HTTP 5xx. 0 filtraciones de datos; alerta de seguridad emitida en < 5 s.
