Introducción al Diseño de Software

Establece las bases para construir software robusto. Domina los principios fundamentales del diseño, comprende su diferencia conceptual con la arquitectura y explora los niveles de diseño (Alto y Bajo).

1. ¿Qué es el Diseño de Software?

El diseño de software es el proceso de planificar y resolver problemas para construir una solución de software estructurada. Actúa como el puente entre el análisis de requerimientos (qué debe hacer el sistema) y la codificación (cómo se programa físicamente). Su objetivo principal es asegurar la mantenibilidad, escalabilidad, legibilidad y reutilización del código.

🧩

Abstracción

Consiste en ocultar los detalles de implementación complejos tras una interfaz simplificada, permitiendo centrarse en qué hace un objeto antes de cómo lo hace.

📦

Encapsulamiento

Agrupa datos y comportamientos en una única unidad lógica (clase), restringiendo el acceso directo a los campos internos mediante modificadores de acceso.

🏛️

Modularidad

Divide un sistema de software complejo en módulos independientes y enfocados que interactúan a través de interfaces bien definidas, facilitando el desarrollo paralelo.

2. Diseño frente a Arquitectura

Aunque relacionados, poseen alcances diferentes. La Arquitectura aborda las decisiones estructurales globales y de infraestructura que son costosas y difíciles de modificar una vez implementadas. El Diseño trata los detalles de implementación dentro de cada módulo, centrándose en el código limpio y los patrones internos.

3. Niveles de Diseño

El diseño de software ocurre en dos niveles de abstracción complementarios: el diseño de **Alto Nivel (HLD)** y el de **Bajo Nivel (LLD)**:

Diseño de Alto Nivel (HLD)

Define la estructura general del sistema: módulos principales, base de datos seleccionada, APIs externas y cómo fluyen los datos a gran escala. No incluye detalles de programación, sino la topología lógica.

Entregables comunes: Diagramas de contenedores (C4 Model Nivel 2), diagramas de arquitectura de red y flujo general de datos.

Diagrama de Alto Nivel (C4 Container)
Frontend (Web App Client)
▼ (REST API HTTP)
Backend Container (REST API Services)
▼ (TCP / Port 5432)
Base de Datos PostgreSQL

Diseño de Bajo Nivel (LLD)

Define el detalle técnico de los componentes individuales de software: estructura de clases, firmas de métodos, tipos de datos, patrones de diseño GoF locales y algoritmos internos que ejecutarán la lógica de negocio.

Entregables comunes: Diagramas de clase UML detallados, especificación de contratos de interfaces y lógica interna en pseudocódigo.

Diagrama UML de Bajo Nivel
UserController
- userService: UserService
+ createUser(dto: UserDto): ResponseEntity
+ getUserById(id: Long): User
▼ (Asociación)
<<interface>> UserRepository
+ save(user: User): User
+ findById(id: Long): Optional<User>
