Laboratorio: Detección de Code Smells y Refactorización SOLID

En este laboratorio técnico reestructuramos un módulo monolítico y acoplado (God Class) perteneciente al núcleo transaccional, aplicando sistemáticamente principios SOLID y patrones GRASP para restaurar su mantenibilidad.

🦨 1. El Código Legado: "InscripcionManager.java"

Inspecciona el siguiente fragmento real. Observa cómo mezcla SQL JDBC, lógica de validación, envío de correos, formateo y cálculo de becas con condicionales rígidos:

❌ InscripcionManager.java (Antipatrón God Class / Violación de SRP, OCP, DIP) 
public class InscripcionManager {
    // Mal olor: Conexión estricta a base de datos dentro de la lógica
    public void procesarInscripcion(String estudianteId, List<String> materiasIds, String tipoBeca) {
        Connection conn = DriverManager.getConnection("jdbc:postgresql://localhost:5432/siga", "admin", "1234");
        
        // Mal olor: Long Method y cálculos repetitivos
        double total = 0;
        for (String id : materiasIds) {
            PreparedStatement ps = conn.prepareStatement("SELECT costo, cupo FROM materias WHERE id = ?");
            ps.setString(1, id);
            ResultSet rs = ps.executeQuery();
            if (rs.next()) {
                if (rs.getInt("cupo") <= 0) {
                    throw new RuntimeException("Sin cupo");
                }
                total += rs.getDouble("costo");
            }
        }

        // Mal olor: Switch Statement / Violación de OCP (Open/Closed)
        if (tipoBeca.equals("ACADEMICA")) {
            total = total * 0.70;
        } else if (tipoBeca.equals("DEPORTIVA")) {
            total = total * 0.80;
        } else if (tipoBeca.equals("EMPLEADO")) {
            total = total * 0.50;
        }

        // Mal olor: Acoplamiento de persistencia directa
        PreparedStatement insert = conn.prepareStatement("INSERT INTO matriculas VALUES (?, ?)");
        insert.setString(1, estudianteId);
        insert.setDouble(2, total);
        insert.executeUpdate();

        // Mal olor: Acoplamiento de infraestructura / Sin inyección
        SmtpTransport.sendEmail("admin@unibe.edu.ec", "Matrícula procesada: $" + total);
    }
}

🩺 2. Matriz de Diagnóstico de Code Smells

Mal Olor (Code Smell) Principio Violado Técnica de Refactorización a Aplicar
God Class / Large Class SRP (Single Responsibility) Extract Class: Separar en Controlador, Servicio de Negocio y Repositorio.
Switch / Conditional Complexity OCP (Open/Closed) Replace Conditional with Polymorphism (Strategy Pattern): Crear jerarquía de cálculo de becas.
Hardcoded SMTP Dependency DIP (Dependency Inversion) Extract Interface & Inversion of Control: Inyectar NotificadorService por constructor.
Primitive Obsession Information Expert (GRASP) Preserve Whole Object / Value Object: Encapsular valores monetarios en Money o BigDecimal.

⚖️ 3. Código Refactorizado: Aplicando SOLID & Clean Code

1. Estrategia de Descuento (OCP)
public interface PoliticaDescuento {
    BigDecimal aplicar(BigDecimal total);
}

@Component("ACADEMICA")
public class DescuentoAcademico implements PoliticaDescuento {
    public BigDecimal aplicar(BigDecimal total) {
        return total.multiply(new BigDecimal("0.70"));
    }
}

@Component("DEPORTIVA")
public class DescuentoDeportivo implements PoliticaDescuento {
    public BigDecimal aplicar(BigDecimal total) {
        return total.multiply(new BigDecimal("0.80"));
    }
}
2. Servicio Desacoplado (SRP & DIP)
@Service
public class InscripcionService {
    private final MateriaRepository materiaRepo;
    private final MatriculaRepository matriculaRepo;
    private final NotificadorService notificador;
    private final Map<String, PoliticaDescuento> politicas;

    @Autowired // Inyección por constructor
    public InscripcionService(MateriaRepository mRepo,
                              MatriculaRepository matRepo,
                              NotificadorService notif,
                              Map<String, PoliticaDescuento> pols) {
        this.materiaRepo = mRepo;
        this.matriculaRepo = matRepo;
        this.notificador = notif;
        this.politicas = pols;
    }

    @Transactional
    public Matricula registrar(String estudianteId, List<String> materiasIds, String beca) {
        List<Materia> materias = materiaRepo.findAllById(materiasIds);
        materias.forEach(Materia::validarCupoDisponible);

        BigDecimal subtotal = materias.stream()
            .map(Materia::getCosto)
            .reduce(BigDecimal.ZERO, BigDecimal::add);

        PoliticaDescuento estrategia = politicas.getOrDefault(beca, t -> t);
        BigDecimal total = estrategia.aplicar(subtotal);

        Matricula mat = matriculaRepo.save(new Matricula(estudianteId, total));
        notificador.enviar("admin@unibe.edu.ec", "Matrícula confirmada");
        return mat;
    }
}

✅ 4. Lista de Cotejo para la Revisión de Código (Code Review) - 10 Pts

Las clases están modularizadas: el servicio no contiene código SQL directo ni llamadas de bajo nivel de transporte.
Se reemplazaron los bloques de if-else o switch por polimorfismo mediante el patrón Strategy o interfaces extensibles.
El servicio depende de interfaces (MateriaRepository, NotificadorService) y recibe las instancias por constructor sin instanciar con new.
Uso de BigDecimal para dinero, nombres expresivos de variables y métodos pequeños (< 25 líneas).
