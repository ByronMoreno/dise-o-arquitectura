Taller UML 1: Casos de Uso y Modelo de Dominio

En este taller práctico modelarás la solución estructural para el núcleo del sistema institucional utilizando notación formal UML 2.5 y código PlantUML verificable.

🏛️ Dominio del Proyecto: Sistema de Gestión Académica y Matrículas (SIGA)

El sistema debe permitir que los Estudiantes consulten asignaturas habilitadas, verifiquen prerrequisitos (obligatorio antes de confirmar la inscripción), registren su matrícula ordinaria o extraordinaria, y realicen el pago de aranceles mediante tarjeta de crédito o transferencia bancaria validada por el ERP financiero. Asimismo, los Docentes registran notas de parciales y asistencia, mientras que el Coordinador de Carrera aprueba convalidaciones especiales.

👤 Entregable 1: Diagrama de Casos de Uso en PlantUML

Copia este script en PlantText o en la extensión PlantUML de VS Code para renderizar el diagrama:

casos_de_uso_siga.puml 
@startuml
left to right direction
skinparam packageStyle rectangle
skinparam actorStyle awesome
skinparam monochrome false

actor "Estudiante" as est
actor "Docente" as doc
actor "Coordinador Académico" as coord
actor "Pasarela de Pagos Externa" as pasarela <<Sistema>>

rectangle "Sistema de Gestión Académica (SIGA)" {
    usecase "CU01: Consultar Asignaturas Habilitadas" as CU01
    usecase "CU02: Matricular Asignaturas" as CU02
    usecase "CU03: Validar Prerrequisitos Académicos" as CU03
    usecase "CU04: Realizar Pago en Línea" as CU04
    usecase "CU05: Aplicar Beca o Descuento" as CU05
    usecase "CU06: Registrar Calificaciones" as CU06
    usecase "CU07: Aprobar Matrícula Especial" as CU07
}

est --> CU01
est --> CU02
doc --> CU06
coord --> CU07

CU02 .--> CU03 : <<include>>
CU04 .--> CU02 : <<extend>>
CU05 .--> CU04 : <<extend>>
CU04 --> pasarela
@enduml

📦 Entregable 2: Diagrama de Clases del Modelo de Dominio

modelo_dominio_siga.puml 
@startuml
skinparam classAttributeIconSize 0
skinparam class {
    BackgroundColor #0f172a
    BorderColor #8b5cf6
    FontColor #f1f5f9
    ArrowColor #38bdf8
}

abstract class Usuario {
    # id: Long
    # cedula: String
    # nombres: String
    # apellidos: String
    # email: String
    + getNombreCompleto(): String
}

class Estudiante {
    - codigoBanner: String
    - semestreActual: Integer
    + tieneDeudas(): Boolean
}

class Docente {
    - especialidad: String
    - horasContratadas: Integer
}

class Matricula {
    - numeroOrden: String
    - fechaRegistro: LocalDateTime
    - estado: String
    - valorTotal: BigDecimal
    + calcularTotal(): BigDecimal
}

class ItemMatricula {
    - id: Long
    - arancel: BigDecimal
    - vecesCursada: Integer
}

class Paralelo {
    - id: Long
    - aula: String
    - cupoMaximo: Integer
    - cupoDisponible: Integer
    + reservarCupo(): Boolean
}

class Asignatura {
    - codigo: String
    - nombre: String
    - creditos: Integer
    + verificarPrerrequisito(est: Estudiante): Boolean
}

Usuario <|-- Estudiante
Usuario <|-- Docente

Estudiante "1" -- "0..*" Matricula : Solicita >
Matricula "1" *-- "1..*" ItemMatricula : Contiene >
ItemMatricula "0..*" -- "1" Paralelo : En >
Paralelo "0..*" -- "1" Asignatura : Dicta >
Docente "1" -- "0..*" Paralelo : Asignado >
@enduml

📊 Rúbrica de Calificación Taller UML 1 (10.0 Pts)

Uso correcto de actores dentro/fuera del límite, semántica estricta de <<include>> y <<extend>> sin invertir las flechas.
Redacción exhaustiva de precondiciones, flujo básico paso a paso, al menos 2 flujos alternativos y postcondiciones comprobables.
Diferenciación exacta entre Agregación y Composición, multiplicidades en ambos extremos y modelado de herencia / abstracción.
Sintaxis limpia sin errores de compilación, layout legible y estilos aplicados acordes al estándar institucional.
