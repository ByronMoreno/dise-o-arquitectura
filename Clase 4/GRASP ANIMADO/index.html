01

Information Expert (Experto en Información)

Metáfora: "Don Ramón el cajero metiéndole la mano al bolsillo al cliente en vez de dejar que el cliente cuente su dinero."

¡OIGA! 😡 ¿Por qué el controlador me mete la mano en el bolsillo, saca mis productos y hace las cuentas con los dedos? ¡Si soy el Pedido, yo sé cuánto sumo!

📖 La Metáfora de la Vida Real

Cuando vas a comprar un helado, el cajero no te saca la billetera del pantalón para contar tus monedas. Tú eres el experto en tu dinero: cuentas y entregas el valor total.

Regla de Asignación: La responsabilidad de calcular el total le pertenece a Pedido y DetallePedido, porque ellos tienen los datos.

Principio: Experto en Información
❌ Violación: Controlador sumando productos Java 21 / Spring Boot 
@PostMapping("/total")
public double calcularTotal(Pedido p) {
    double total = 0;
    // ❌ El controlador hace un trabajo ajeno
    for (Producto prod : p.getProductos()) {
        total += prod.getPrecio() * prod.getCantidad();
    }
    return total;
}
02

Creator (Creador)

Metáfora: "El mesero corriendo a la mesa con una lechuga cruda y pan frío para armar la hamburguesa frente al cliente."

¡Qué desastre en el comedor! 😱 El controlador intenta crear cada DetallePedido a mano y ensamblarlos en la mesa. ¡Si olvida la lechuga, la hamburguesa explota!

📖 La Metáfora de la Vida Real

El mesero no cocina ni arma los ingredientes en la mesa. La cocina (el Pedido) recibe los ingredientes y ensambla la hamburguesa de forma segura y completa.

Regla de Asignación: Pedido contiene y agrega a DetallePedido, por lo tanto Pedido debe tener el método agregarDetalle(producto, cantidad).

Principio: Creador
❌ Violación: Controlador instanciando detalles Java 21 / Spring Boot 
// ❌ El controlador conoce cómo instanciar cada parte
DetallePedido d = new DetallePedido();
d.setCantidad(item.cantidad());
d.setProducto(prod);
pedido.getDetalles().add(d);
03

Controller (Controlador)

Metáfora: "El piloto de avión que intenta despachar boletos, cargar combustible y pilotar al mismo tiempo."

¡Nos vamos a estrellar! ✈️💥 El PedidoController está recibiendo el HTTP, consultando SQL, calculando impuestos y enviando correos todo dentro del endpoint.

📖 La Metáfora de la Vida Real

El piloto vuela el avión; no vende refrigerios en la puerta de abordaje. La Torre de Control recibe la señal de radio y coordina a los equipos de pista.

Regla de Asignación: El @RestController solo recibe la petición HTTP y delega inmediatamente a PedidoService (el controlador de caso de uso).

Principio: Controlador
❌ Violación: Endpoint con 100 líneas de lógica Java 21 / Spring Boot 
@PostMapping
public Pedido crear(@RequestBody PedidoRequest req) {
    // ❌ Busca en BD, calcula, envía correos...
    // ¡El controlador hace el trabajo de toda la empresa!
    return repository.save(pedido);
}
04

Low Coupling (Bajo Acoplamiento)

Metáfora: "El astronauta pegado con cemento a la turbina del cohete."

¡Estoy atrapado! 🚀 Me pegaron al cohete con new EmailService(). Si queremos viajar a Marte usando WhatsApp, ¡tienen que desarmarme entero!

📖 La Metáfora de la Vida Real

Nadie suelda su cargador de celular a la batería del auto. Usas un cable USB estándar: si cambias de celular o de auto, el conector sigue funcionando.

Regla de Asignación: Diseña las clases para que conozcan abstracciones (`Notificador`) y no implementaciones concretas, minimizando el impacto de los cambios.

Principio: Bajo Acoplamiento
❌ Violación: new EmailService() soldado Java 21 / Spring Boot 
@Service
public class PedidoService {
    // ❌ Atado de por vida a Email
    private final EmailService email = new EmailService();
}
05

High Cohesion (Alta Cohesión)

Metáfora: "El Doctor-Mecánico-Peluquero que te arregla los frenos y te opera el apéndice con la misma llave inglesa."

¡Tranquilo, no se mueva! 💉🔧 Mientras le cambio las bujías al motor, le saco una muela y le declaro los impuestos en SistemaService.

📖 La Metáfora de la Vida Real

¿Dejarías que un mecánico te haga una endodoncia con su taladro de llantas? Cada profesión tiene su campo y su instrumental.

Regla de Asignación: Una clase altamente cohesiva solo contiene métodos estrechamente relacionados con su especialidad (`PedidoService` solo atiende pedidos).

Principio: Alta Cohesión
❌ Violación: Clase "Bolsa de Gatos" Java 21 / Spring Boot 
@Service
public class SistemaService {
    void crearPedido() { ... }
    void declararImpuestos() { ... }
    void cambiarAceite() { ... }
}
06

Polymorphism (Polimorfismo)

Metáfora: "El auto con 3 volantes diferentes: uno para doblar en asfalto, otro en tierra y otro en nieve."

¡Voy a chocar! 🚗💥 Para cada tipo de envío tengo que soltar el volante y buscar otra palanca en una cadena infinita de if / else if.

📖 La Metáfora de la Vida Real

Un auto moderno tiene un solo volante universal. No cambias de timón según la calle: el auto delega la tracción a sus ruedas inteligentemente.

Regla de Asignación: Cuando el comportamiento varía según el tipo, crea una interfaz (`TipoEnvio`) y delega el cálculo a cada clase especialista.

Principio: Polimorfismo
❌ Violación: if/else por tipo Java 21 / Spring Boot 
if (tipo.equals("NORMAL")) return p * 2;
else if (tipo.equals("EXPRESS")) return p * 5;
else if (tipo.equals("INTER")) return p * 10;
07

Pure Fabrication (Fabricación Pura)

Metáfora: "El cliente cargando archivadores de metal en la espalda vs El Robot Bibliotecario inventado."

¡Me aplasta la base de datos! 🗄️ La entidad Pedido representa una compra, pero le metieron código JDBC, transacciones SQL y conexiones de red en su cuerpo.

📖 La Metáfora de la Vida Real

En el mundo real no existe un "Repositorio". Los clientes compran productos, no repositorios. Pero inventar ese robot archivador artificial evita que el cliente cargue el peso de la base de datos.

Regla de Asignación: Crea clases que no existan en el negocio (`PedidoRepository`) para encargarse de aspectos puramente técnicos (SQL, serialización).

Principio: Fabricación Pura
❌ Violación: Pedido con código SQL JDBC Java 21 / Spring Boot 
public class Pedido {
    // ❌ La entidad de negocio maneja base de datos
    public void guardarEnPostgres() {
        Connection con = DriverManager.getConnection(...);
    }
}
08

Indirection (Indirección)

Metáfora: "Gritarle directamente en español a un banquero japonés vs Contratar a un traductor de la ONU."

¡No entiendo nada! 🤯 PagoService tiene que saber hablar el dialecto exacto de PayPal y Stripe. ¡Si PayPal actualiza su API, mi tienda quiebra!

📖 La Metáfora de la Vida Real

En la asamblea de la ONU los presidentes no aprenden 193 idiomas. Usan un auricular con traductor simultáneo. El traductor es el intermediario.

Regla de Asignación: Pon un adaptador intermediario (`PasarelaPago`) entre tu negocio y la API de terceros. Tu código solo habla con el adaptador.

Principio: Indirección
❌ Violación: Acoplado al SDK externo Java 21 / Spring Boot 
@Service
public class PagoService {
    // ❌ Conoce la API propietaria de PayPal
    PayPalApi api = new PayPalApi();
    api.realizarPago(monto);
}
09

Protected Variations (Variaciones Protegidas)

Metáfora: "Construir una casa con techo de cristal que se inunda con cada llovizna vs Poner un paraguas blindado."

¡Nos inundamos! 🌧️ El proveedor del precio del dólar cambió su JSON sin avisar y nuestra lógica de compras dejó de funcionar en producción.

📖 La Metáfora de la Vida Real

Si sabes que en tu ciudad llueve mucho, no sales en camisa de papel. Llevas un paraguas impermeable.

Regla de Asignación: Identifica los puntos inestables (cotizaciones, aduanas, pasarelas) y crea una interfaz blindada alrededor de ellos. Si el proveedor cambia, tu negocio ni se entera.

Principio: Variaciones Protegidas
❌ Violación: Consulta cruda a API inestable Java 21 / Spring Boot 
@Service
public class CompraService {
    // ❌ Sin protección ante caídas o cambios del tercero
    BigDecimal tasa = HttpClient.get("https://api-volatil.com");
}
