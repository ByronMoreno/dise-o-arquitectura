1. La Pirámide de Testing de Software

La Pirámide de Testing es un marco de diseño propuesto por Mike Cohn para estructurar las pruebas de software de forma eficiente. Establece que un sistema saludable debe tener una gran base de pruebas unitarias rápidas y económicas, y un número reducido de pruebas E2E complejas y costosas:

E2E (Extremo a Extremo)
Simula flujos de usuario reales en el navegador. (Playwright, Cypress)
Integración & Mocking
Prueba la comunicación entre componentes. (Mockito)
Unitario (Unit Testing)
Prueba funciones y clases aisladas. (JUnit, Jest, PyTest)
▲ Mayor costo y tiempo de ejecución (E2E) ▼ Más veloces, económicos y aislados (Unitarios)

JUnit

Lenguaje: Java | Nivel: Pruebas Unitarias

El framework de pruebas unitarias estándar de facto en Java. Su quinta versión (JUnit 5 / Jupiter) incorpora pruebas parametrizadas avanzadas, inyección de dependencias en constructores de pruebas y soporte nativo para aserciones lambda de Java 8.

Fortalezas (Pros)

  • Integración perfecta en compiladores de Java (Gradle/Maven).
  • Extremadamente rápido al probar código aislado.
  • Gran soporte de extensiones (@ExtendWith).

Debilidades (Cons)

  • Limitado a la capa de lógica, no simula interfaces de usuario.
  • Requiere configuraciones complejas para levantar contextos Spring Boot completos.

3. Comparación de Código: Casos de Prueba Reales

Compara la sintaxis exacta necesaria para estructurar aserciones, mocks unitarios y pruebas de interacción E2E en el navegador: 

@ExtendWith(MockitoExtension.class)
class UsuarioServiceTest {

    @Mock
    private UsuarioRepository repository;

    @InjectMocks
    private UsuarioService service;

    @Test
    void debeRetornarUsuario() {
        // Simular comportamiento del Mock
        Mockito.when(repository.findByEmail("test@mail.com"))
               .thenReturn(Optional.of(new Usuario("Juan")));

        Usuario resultado = service.buscar("test@mail.com");
        assertEquals("Juan", resultado.getNombre());
    }
}
