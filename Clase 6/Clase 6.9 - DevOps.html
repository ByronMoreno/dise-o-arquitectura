Herramientas y Frameworks DevOps

Aprende el ciclo de vida de la infraestructura moderna. Domina contenedores, orquestadores, integración/despliegue continuo (CI/CD) e infraestructura como código (IaC).

1. Ciclo de Vida DevOps & Categorías

El paradigma DevOps unifica el desarrollo de software (Dev) y las operaciones de sistemas (Ops). Su principal objetivo es automatizar cada fase del ciclo de vida para realizar despliegues rápidos, seguros y predecibles. Las herramientas se dividen en tres áreas críticas:

📦

Contenedores y Orquestación

Aíslan las aplicaciones a nivel de sistema operativo eliminando el clásico "en mi máquina funciona" (Docker) y coordinan dinámicamente miles de contenedores distribuidos en clusters de servidores (Kubernetes, Swarm).

🔄

CI/CD & GitOps

Automatizan las fases de compilación, ejecución de tests y despliegue físico ante eventos del código (Jenkins, GitHub Actions, GitLab CI). Con GitOps (ArgoCD), el repositorio Git es la única fuente de verdad del estado de la infraestructura.

📜

IaC & Configuración

Permiten definir de forma declarativa mediante archivos de código toda la infraestructura cloud (Terraform) y configurar en bloque las dependencias y paquetes de cientos de servidores remotos sin agentes (Ansible).

2. Catálogo e Interactividad DevOps

Selecciona cada botón para explorar el tipo de herramienta, su filosofía operativa, sus pros/contras y su diagrama estructural:

Docker

Virtualización OS

Empaqueta la aplicación, dependencias, variables y librerías en un único contenedor portátil e independiente. Utiliza características de aislamiento del Kernel de Linux (namespaces y cgroups) para ejecutar procesos de forma aislada sin levantar un hipervisor (máquina virtual pesada).

Fortalezas (Pros)

  • Arranque de contenedores en milisegundos.
  • Inmutabilidad: la misma imagen corre en local y producción.
  • Eficiente en consumo de recursos de CPU y RAM.

Debilidades (Cons)

  • Menor aislamiento de seguridad comparado con máquinas virtuales puras.
  • Gestión de almacenamiento persistente (Volúmenes) algo compleja.

# Multi-stage Dockerfile para optimizar espacio
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:18-alpine AS runner
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
EXPOSE 3000
CMD ["node", "dist/main.js"]
name: CI/CD Pipeline
on:
  push:
    branches: [ main ]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v3

      - name: Install NodeJS
        uses: actions/setup-node@v3
        with:
          node-version: 18

      - run: npm ci
      - run: npm test
