Módulo de Persistencia y Datos

Frameworks de Persistencia

Conoce la taxonomía completa de la persistencia de datos. Analiza y compara a fondo los enfoques de ORMs relacionales, ODMs para documentos NoSQL y SQL Mappers.

1. ORMs frente a ODMs y SQL Mappers

En el desarrollo de software, la persistencia se encarga de guardar y recuperar el estado de los objetos de negocio. Sin embargo, según el tipo de base de datos y el nivel de abstracción del lenguaje SQL o NoSQL, las herramientas se clasifican en tres enfoques diferenciados:

📊

ORM (Object-Relational Mapper)

Traduce y mapea objetos lógicos de la aplicación hacia tablas de bases de datos relacionales SQL. Abstrae completamente las consultas físicas, autogenerando el SQL (ej. Hibernate, Prisma, Entity Framework).

📄

ODM (Object-Document Mapper)

Traduce objetos de la aplicación hacia bases de datos documentales NoSQL (como MongoDB). Mapea clases a esquemas estructurados de documentos JSON/BSON, aplicando reglas de validación (ej. Mongoose).

⚙️

SQL Mappers (Data Mappers directos)

No ocultan la base de datos SQL ni intentan abstraerla. En su lugar, facilitan mapear directamente los parámetros y resultados de consultas SQL puras que escribe a mano el programador hacia objetos de dominio (ej. MyBatis).

Hibernate

Categoría: ORM | DB: Relacionales (SQL)

El estándar del ecosistema Java que implementa la especificación de JPA. Traduce las llamadas y consultas a base de datos de manera automática a SQL nativo, aislando al programador del dialecto SQL específico de la base de datos (PostgreSQL, MySQL, Oracle).

Fortalezas (Pros)

  • Independencia total del motor de base de datos.
  • Mapeo avanzado de relaciones jerárquicas y herencias.
  • Manejo nativo de transacciones complejas.

Debilidades (Cons)

  • Gran complejidad y sobrecarga de memoria.
  • Dificultad de optimización para queries sumamente optimizadas.

const mongoose = require('mongoose');

// Uso (Active-record style)

public class Producto {

// Mapeo directo y control del SQL puro
public interface ProductoMapper {
    @Insert("INSERT INTO productos(nombre, precio) VALUES(#{nombre}, #{precio})")

    @Select("SELECT * FROM productos WHERE id = #{id}")
    Producto obtenerPorId(long id);
}
