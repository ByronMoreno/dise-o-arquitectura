Antipatrones Arquitectónicos

Aprende a identificar, documentar y refactorizar los errores sistemáticos de diseño de software más comunes. Evita fallas estructurales graves en tu arquitectura.

1. ¿Qué es un Antipatrón?

Un antipatrón es un patrón de diseño que parece una solución excelente al principio, pero que en la práctica atrae consecuencias negativas extremas y costosas a largo plazo (deuda técnica). A diferencia de un error común, es una solución repetitiva estructurada que se comete sistemáticamente por falta de experiencia, prisa o aplicación errónea de conceptos.

Patrón de Diseño

Solución probada, estructurada e idónea a un problema recurrente. Promueve la mantenibilidad, extensibilidad y modularidad.

Antipatrón Arquitectónico

Solución mal planteada que genera acoplamiento rígido, rompe modularidad, ralentiza el desarrollo y fosiliza el código fuente.

Nivel: Arquitectura Global

Un sistema estructurado sin una arquitectura definida. Se caracteriza por un crecimiento caótico donde cada módulo se conecta con cualquier otro de forma ad-hoc, resultando en una red impenetrable de dependencias circulares.

Causas comunes

  • Falta de liderazgo técnico o arquitecto de software.
  • Desarrolladores apurados agregando parches rápidos.
  • Crecimiento descontrolado de requerimientos.

Cómo solucionarlo

  • Definir límites de dominios claros (Bounded Contexts).
  • Refactorizar gradualmente hacia arquitecturas limpias o en capas.
  • Bloquear dependencias circulares mediante análisis estático.

3. Comparativa de Código de Refactorización

Revisa estos casos prácticos que demuestran cómo identificar un antipatrón en el código y cómo refactorizarlo a una estructura limpia: 

// Antipatrón: Clase única que hace todo (Base de datos, Reportes, E-mail y Pagos)
public class SuperCustomerService {
    
    public void saveCustomer(Customer c) {
        // 1. Conexión manual a BD y query SQL
        Connection conn = DriverManager.getConnection("jdbc:mysql...");
        PreparedStatement ps = conn.prepareStatement("INSERT INTO...");
        ps.executeUpdate();
    }
    
    public void sendWelcomeEmail(Customer c) {
        // 2. Configuración SMTP y envío de correo
        Properties props = new Properties();
        props.put("mail.smtp.host", "smtp.server.com");
        // lógica de SMTP pesada...
    }
    
    public void processCardPayment(Customer c, double amount) {
        // 3. Conexión externa a Stripe / Gateway
    }
}
// Solución: Clases desacopladas respetando Responsabilidad Única (SRP)
public class CustomerRepository {
    public void save(Customer c) { /* Lógica de BD */ }
}

public class EmailService {
    public void sendWelcomeEmail(Customer c) { /* Lógica de Email */ }
}

public class PaymentProcessor {
    public void chargeCard(Customer c, double amount) { /* Lógica de Pagos */ }
}

// Coordinador liviano
public class CustomerFacade {
    private CustomerRepository repo;
    private EmailService email;
    
    public void registerCustomer(Customer c) {
        repo.save(c);
        email.sendWelcomeEmail(c);
    }
}
// Flujo duplicado (Copy & Paste) y dependencias enmarañadas manuales
function getUsers() {
  const db = new DatabaseConnection();
  db.connect();
  const query = "SELECT * FROM users";
  const data = db.execute(query);
  db.close();
  return data;
}

function getProducts() {
  // Código copiado idénticamente cambiando solo el String del Query
  const db = new DatabaseConnection();
  db.connect();
  const query = "SELECT * FROM products";
  const data = db.execute(query);
  db.close();
  return data;
}
// Solución: Abstracción de conexión en un único punto reutilizable
async function executeQuery(query) {
  const db = new DatabaseConnection();
  try {
    await db.connect();
    return await db.execute(query);
  } finally {
    await db.close();
  }
}

// Consumo limpio sin duplicados
const users = await executeQuery("SELECT * FROM users");
const products = await executeQuery("SELECT * FROM products");
