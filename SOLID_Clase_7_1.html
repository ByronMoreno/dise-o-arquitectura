Principios SOLID

Domina los cinco acrónimos de diseño orientado a objetos formulados por Robert C. Martin. Diseña clases cohesivas, extensibles y fáciles de mantener.

1. ¿Qué es SOLID?

El acrónimo SOLID representa cinco principios básicos de diseño de clases que guían al desarrollador para construir software limpio, reduciendo el acoplamiento rígido y la fragilidad del código. Su correcta aplicación permite cambiar o extender el comportamiento del sistema sin necesidad de rediseñar o reescribir gran parte de la base de código.

S

Responsabilidad Única

Una clase debe tener una sola razón para cambiar, enfocándose en una única tarea.

O

Abierto / Cerrado

Las clases deben estar abiertas a la extensión pero cerradas a la modificación.

L

Sustitución de Liskov

Las subclases deben poder ser sustituidas por sus clases padre sin romper el sistema.

SRP - Single Responsibility Principle

Responsabilidad Única

Cada clase, módulo o función debe encargarse de un único aspecto de la lógica del sistema. Esto simplifica su comprensión, facilita las pruebas unitarias y minimiza la posibilidad de romper funcionalidades no relacionadas cuando se realizan cambios.

Beneficios

  • Código altamente cohesivo.
  • Facilidad de mantenimiento y pruebas unitarias.
  • Menor riesgo de conflictos en fusiones (merges) de git.

Señales de Alerta

  • Clases gigantes ('God Objects') con miles de líneas.
  • La clase importa librerías de múltiples capas (BD, email, UI).

3. Ejemplos de Código (Java y Python)

Compara la sintaxis y los enfoques de refactorización limpia para cada principio SOLID: 

// ANTES: Clase con múltiples responsabilidades (Negocio + Guardar BD + Enviar Email)
public class UsuarioService {
    public void registrarUsuario(Usuario user) {
        // Lógica de BD...
        System.out.println("Guardando en MySQL...");
        // Enviar email...
        System.out.println("Enviando correo...");
    }
}

// REFACTORIZADO (SRP): Clases desacopladas
public class UsuarioRepository {
    public void guardar(Usuario u) { /* Lógica BD */ }
}
public class NotificadorEmail {
    public void enviarWelcome(Usuario u) { /* Lógica Email */ }
}
# ANTES: Violación de OCP (modificar la clase ante un nuevo tipo de reporte)
class GeneradorReportes:
    def generar(self, datos, formato):
        if formato == "PDF":
            self._pdf(datos)
        elif formato == "HTML":
            self._html(datos) # Si añades Excel, debes MODIFICAR esta clase.

# REFACTORIZADO (OCP): Abierto a extensión, cerrado a modificación
class ReporteFormato:
    def render(self, datos): pass

class ReportePDF(ReporteFormato):
    def render(self, datos): print("Generando PDF")

class ReporteExcel(ReporteFormato): # Se extiende sin tocar las clases existentes
    def render(self, datos): print("Generando Excel")
// ANTES: Avestruz hereda de Ave pero no vuela (lanza excepción rompiendo polimorfismo)
public class Ave {
    public void volar() { System.out.println("Volando..."); }
}
public class Avestruz extends Ave {
    @Override
    public void volar() { throw new UnsupportedOperationException("No puedo volar"); }
}

// REFACTORIZADO (LSP): Modularidad jerárquica limpia
public class Ave { /* Características generales */ }
public class AveVoladora extends Ave {
    public void volar() { /* Volando */ }
}
public class Avestruz extends Ave { /* Solo camina */ }
# ANTES: Interfaz "gorda" que fuerza a una Impresora simple a programar un FAX
class SuperDispositivo:
    def imprimir(self): pass
    def escanear(self): pass
    def enviar_fax(self): pass

# REFACTORIZADO (ISP): Interfaces específicas segregadas
class Impresora:
    def imprimir(self): pass

class Escaner:
    def escanear(self): pass

class ImpresoraBasica(Impresora):
    def imprimir(self): print("Imprimiendo en papel")
// ANTES: Clase de alto nivel acoplada rígidamente a una base de datos específica (MySQL)
public class GestorPedido {
    private MySQLConnection db = new MySQLConnection(); // Dependencia directa
    public void guardar() { db.insert(); }
}

// REFACTORIZADO (DIP): Ambos dependen de abstracciones (Interfaces)
public interface Database {
    void save();
}
public class GestorPedido {
    private Database db;
    public GestorPedido(Database db) { this.db = db; } // Inyección
    public void guardar() { db.save(); }
}
